# 脚本层总览（内核 + 内容两层）

`scripts/` 分两块（目录结构与内容文件格式见 [scripts-content.md](scripts-content.md)）：

```text
scripts/
  kernel/     # 通用内核：@定义/@实体/@函数/@规则
  rules/      # 规则库：任务/行为等业务规则（只写规则，不写 @实例）
  # 内容（角色/物品/场景/事件条目）不在 scripts/：见 private/ 与 neko-data apply
```

`kernel/` 是**通用底层定义**：所有规则只针对「内核模板」，不含任何角色 ID 或角色数据。
`entities/` 与 `scenes/` 是内容蓝图，**不注册为脚本**，由 `neko-data apply` 物化成实体
（默认不覆盖已有实体的运行时状态）。

## 组合契约

`角色基础`（历史名 `角色基础`）组合下列全部内核；它是**完整的基础角色定义**，不带种族特征时即人族。
种族是组合出来的，不是继承特例：`@实体 角色基础:猫娘 [角色基础, 猫耳, 猫尾, 肉垫] {}`。
任意「基础 + 若干特征」都成立，不要求凑齐某族全套。

**选择器注意**：`角色基础` 是 `角色基础` 的**子类型**，所以 `$[角色基础]` 命中全部角色，
而 `$[角色基础]` 只命中 `角色基础:*` 那一条历史分支。新规则请写 `$[角色基础]`；
现有内核级规则（`$[基础内核]`、`$[代谢内核]`…）在两条分支上都成立，不受影响。

任何需要完整生理模拟的类型，组合以下内核（顺序无关）：

```neko
@实体 你的类型 [基础内核, 行为内核, 代谢内核, 循环内核, 呼吸内核,
                内分泌内核, 器官内核, 伤害内核, 路径内核, 生殖内核, 状态内核,
                交互内核, 行动内核, 规划内核, 教育内核, 交易内核, 记忆内核,
                人格内核, 九型人格内核, 情感内核, 人设内核, 成长内核, 好奇内核,
                社交内核, 环境感受内核, 表情内核, 事件内核] {}
```

部分组合只保证该层自身规则可用；跨层读取的字段若缺失会按 0/字符串处理，**不要做部分组合后再断言数值**。

物品/交互层（L6，7000–7999）负责素材被动结算（变质/耗尽/磨损）与角色×素材的交互结算

规则按 `优先级` 升序执行（数值小的先跑），同优先级按注册顺序。

## 扩展方式

- **新路径**（如尿道/创口）：在 `scripts/kernel/injury/pathTick.neko` 加一条参数规则（阈值/菌量/出血系数）+ 一条「类型 → 靶器官应力」规则，不改函数。
- **新器官**：在 `organModel.neko` 加一块账本 + 一个功能函数；若要参与 MODS，在 `伤害器官衰竭下一步()`
  里加权（注意它读的是结构性 `应力`，不是瞬时 `功能`）。
- **新种族**：在 `baseInitTick.neko` 加一条 500 段规则（11 个 `种族参数.*`），键集必须与现有预设完全一致。
- **新状态词**：在 `statusFunctions.neko` 的 `状态身体分类()` 里加分支，保持阈值链顺序。

## 单位约定

kcal / mL / 0.1°C / mmHg / mg/dL / g / 分钟；比例用千分比（‰），质量占比用万分比。

## 硬编码分类（哪些值该调、去哪里调）

脚本里仍有约 1800 个数字字面量。按「是否需要改」分成三类，新增功能时照此落位：

| 类别 | 判据 | 例子 | 落位 |
|---|---|---|---|
| **定义性常数** | 单位换算或物理约束，换种族/角色都不该变 | `1440`（分钟/天）、`10080`（分钟/周）、`525600`（分钟/年）、`0–100` 上下界 | 留在函数里，不要参数化 |
| **种族差异** | 换种族应该不同 | 体温/心率/呼吸/寿命/成熟年龄/孕期周/周期天/代谢系数/生育上限/**属性修正**/体型系数 | `种族参数.*`（`baseModel` 声明，`baseInitTick` 按种族写入） |
| **难度与手感** | 调整游戏体验时需要改 | 状态分档（濒危/休克/衰竭/脓毒/虚脱）、死亡线、MODS 累积驱动、行动中断、后遗症线、老年/衰退年龄比例 | `判定阈值.*`（`status/thresholdModel.neko`） |
| **曲线斜率** | 想微调数值手感时才动 | `应力 / 25`、`屏障 / 50`、`出血衰减 -5`、`血糖 +吸收/20` | 留在函数里；改动需同步探针基线 |

注意「预留字段」不在此列：`器官性状.长度 / 壁厚` 目前没有内核读取方，但它们是**上层性行为
破裂计算**与器官讲述的输入，属于「已定义、待消费」，不要当死字段删。判断一个字段该不该删，
看的是「它有没有语义归属」，而不是「今天有没有 grep 到读取方」。

**禁止**：在规则/函数里出现具体实体 ID、角色名、种族名。种族差异一律走 `种族参数.*`，
个体差异一律走内容层 `private/` 的 `@实例` 实例覆盖。

### 属性修正的写法

`基础属性*()` 只读两个数据源，不含任何种族分支：

```neko
值 = 50
值 = 值 + {e}.种族参数.属性修正.体质     // baseInitTick 按 种族 写入
if {e}.基础.年龄 > 基础老年年龄() {       // 寿命 × 判定阈值.老年比例
  值 = 值 + (-15)
}
```

新增种族 = 在 `baseInitTick.neko` 加一条 5xx 规则（11 个 `种族参数.*` + 7 个 `属性修正.*`），
不需要改 `baseFunctions.neko`。特征加成（`猫耳.灵敏` / `猫尾.平衡` / `尖耳.感知`）由部位模板自带。

### 实体元数据：`__type__` / `__id__`

脚本读不到实体自身的类型和 ID，会让「类型是 `角色基础:犬娘`、`基础.种族` 却是 `人族`」这类错误完全静默。
引擎提供两个**只读虚拟路径**：

```neko
名 = {e}.__type__     // "角色基础:犬娘"
id = {e}.__id__       // "猫猫"
```

它们不落在 `Data` 里，因此不进快照、不进存档、不可写。`baseInitTick` 用它在 495/515 做
「类型 → 种族」推断与未识别回退，895/896 做冲突标记。

### 条件陷阱：右侧的 `$.路径` 不会被重写

引擎只把条件**左侧**的 `$.x` 重写成 `{e}.x`，右侧原样保留，于是这条规则**恒为假**：

```neko
$.记忆.短期负荷 < $.记忆.遗忘阈值 ∧ $.记忆.短期负荷 > 0   // ✗ 右侧不解析，永不触发
记忆应遗忘() == true                                      // ✓ 比较收进函数体内
```

已因此修过一次 `meForget`（记忆永不遗忘）。凡是要拿两个字段比大小，一律写成一个
`@函数`，函数体里两侧都用 `{e}.`。

### 条件陷阱：括号内的 `∨` 不成立

`(A ∨ B) ∧ C` 这种带括号分组的复合条件实测不生效，规则会恒假。需要「或」就拆成
两条规则：

```neko
// ✗ 恒假
($.行动.当前 = "" ∨ $.行动.阶段 = "完成") ∧ $.行动.阶段 != "空闲" { … }

// ✓ 两条独立规则
$.行动.当前 = "" ∧ $.行动.阶段 != "空闲" { … }
$.行动.阶段 = "完成" { … }
```

已因此修过一次 `acReset`（动作完成态无法回收，动作会无限重启）。

### 单位陷阱：`/` 是浮点除法

`.neko` 的 `/` 和 Python 一样返回浮点，`28 * 36 / 100` 得 `10.08` 而不是 `10`。
凡是拿比例做**边界比较或取整**，必须套 `int()`：

```neko
起点 = int(生殖周期天() * 36 / 100)   // 正确
起点 = 生殖周期天() * 36 / 100         // 错误：日 >= 10.08 会把第 10 天排除
```
