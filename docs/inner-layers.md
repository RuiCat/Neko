# L12 内心层：情感 / 人设 / 九型人格（附记忆闭环）

这层补的是角色「感受到什么、以谁的口吻表达、为什么这样反应」的底层状态机。
它只维护**状态与派生量**，不生成台词；台词仍由决策层（LLM / 行为脚本）读取这些字段后决定。

优先级段 **8500–8599**（L12 自我状态），本层占用：

| 子层 | 优先级 | 目录 | 内核模板 | 写域 |
|---|---|---|---|---|
| 情感 | 8521–8526 | `scripts/kernel/emotion/` | `情感内核` | `情感.*` + `记忆.巩固`（请求） |
| 九型人格 | 8535–8536 | `scripts/kernel/personality/` | `九型人格内核` | `九型.*` |
| 人设 | 8590–8592 | `scripts/kernel/personality/` | `人设内核` | `人设.*` + 顶层 `自称`/`对主人称呼`（同步） |

三者都组合进 `@实体 NPC`（`scripts/kernel/metabolism/metabolismAttach.neko`），
因此已有 `NPC` / `NPC:*` 实体无需迁移：新增字段通过模板回退可读。

## 1. 情感内核（`scripts/kernel/emotion/`）

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `情感.情绪` | str | 当前离散情绪；由事件标签或八象限派生，低强度时复位为 `平静` |
| `情感.效价` | int -100–100 | 愉悦度：负=不快，正=愉快 |
| `情感.唤醒` | int 0–100 | 激活度：低=疲惫/平静，高=兴奋/紧张 |
| `情感.强度` | int 0–100 | 本次情绪强度；每 tick -1 |
| `情感.余温` | int 0–100 | 情绪残留；触发时取 max(旧余温, 新强度) |
| `情感.依恋` | int 0–100 | 对主人的依恋，向 `(主人互动 + 长期记忆)/2` 慢移 |
| `情感.基线` | int -100–100 | 由大五人格派生的心情基线 |
| `情感.触发源` | str | 最近一次事件的来源描述 |
| `情感.事件效价` | int -100–100 | **上层输入**：本次事件对效价的增量 |
| `情感.事件唤醒` | int -100–100 | **上层输入**：本次事件对唤醒的增量 |
| `情感.事件情绪` | str | **上层输入**：离散情绪标签（空=按效价/唤醒派生） |
| `情感.事件源` | str | **上层输入**：写进 `触发源` |
| `情感.记忆类别` | str | **上层输入**：`关系` / `事件` / `自我`，默认 `事件` |
| `情感.待印记` | int 0–100 | 给记忆层的情绪印记增量 |
| `情感.待记忆` | int 0–100 | 给记忆层的通道记忆增量 |
| `情感.固化标记` | bool | 防止高强度情绪每 tick 重复请求巩固 |

规则（前缀 `em`）：

1. `emDecay`（8521）：`流逝分钟>0` 时效价向基线 ±1、唤醒向 30 ±1、强度/余温 -1、依恋向目标 ±1。
2. `emCalm`（8522）：强度 ≤15、无待处理事件且情绪非平静 → 情绪复位为 `平静`。
3. `emTrigger`（8523）：有事件时应用增量并夹紧；情绪 = `事件情绪`（非空）或效价/唤醒八象限；
   记录触发源、归一记忆类别，清空事件字段。
4. `emImprint`（8524）：强度 ≥60 → 待印记 = 强度/4；强度 ≥70 → 待记忆 = 强度/3。
5. `emConsolidate`（8525）：强度 ≥80 且记忆内核存在 → 置 `记忆.巩固=true`，并置固化标记。
6. `emReset`（8526）：强度 <40 → 清固化标记。

八象限（`情感下一步情绪`）：效价 ≥30 且唤醒 ≥60=兴奋，≥30=愉快，否则安心；
效价 ≤-30 且唤醒 ≥60=愤怒，≥30=焦虑，否则低落；中间区唤醒 ≥60=紧张，≤20=疲惫，否则平静。

**上层触发方式**（MCP `entity_set` 或脚本写入，然后下一次 tick）：

```json
{
  "情感": {
    "事件效价": -60,
    "事件唤醒": 70,
    "事件情绪": "愤怒",
    "事件源": "被主人责骂",
    "记忆类别": "关系"
  }
}
```

## 2. 九型人格内核（`scripts/kernel/personality/`）

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `九型.类型` | int 0–9 | 0=未设定；1 完美 / 2 助人 / 3 成就 / 4 浪漫 / 5 观察 / 6 忠诚 / 7 活跃 / 8 领袖 / 9 和平 |
| `九型.类型名` | str | 类型中文名（派生） |
| `九型.侧翼` | str | 数据字段，如 `4w5`，规则不猜 |
| `九型.中心` | str | 本能（1/8/9）/ 情感（2/3/4）/ 思维（5/6/7） |
| `九型.整合方向` | int | 健康时吸收的方向：1→7、2→4、3→6、4→1、5→8、6→9、7→5、8→2、9→3 |
| `九型.分裂方向` | int | 压力下滑落的方向：1→4、2→8、3→9、4→2、5→7、6→3、7→1、8→5、9→6 |
| `九型.核心恐惧` / `核心欲望` / `防御机制` | str | 类型档案 |
| `九型.压力值` | int 0–100 | `孤单/2 + 疼痛/3 + 情绪印记/5 + 负效价/4` |
| `九型.成长值` | int 0–100 | `长期记忆/2 + 主人互动/2` |
| `九型.健康层级` | int 1–9 | `5 - 成长/25 + 压力/25`，夹在 1..9；1 最健康 |
| `九型.应激反应` | str | 层级 ≤3=`整合`，≥7=`分裂`，其余 `常态` |
| `九型.上次类型` | int 0–9 | 类型变化检测 |

规则（前缀 `en`）：

1. `enDerive`（8535）：`类型>0` 且（首次 / 中心为空 / 类型变化）→ 重算静态档案。
2. `enDynamics`（8536）：每 tick 由社交、伤害、情感、记忆派生压力/成长/层级/应激。

## 3. 人设内核（`scripts/kernel/personality/`）

`人设.*` 是**数据**，不是行为：

| 字段 | 类型 | 含义 |
|---|---|---|
| `人设.自称` | str | 第一人称 |
| `人设.对主人称呼` | str | 第二人称 |
| `人设.性格标签` | list | 如 `["爱撒娇","傲娇"]` |
| `人设.说话语气` | str | 语气描述 |
| `人设.口头禅` | list | 口癖 |
| `人设.背景` | str | 背景设定 |
| `人设.禁忌` | list | 不可跨越的设定 |
| `人设.表达倾向` | str | 派生：`健康层级/中心/当前情绪/MBTI` 合成标签 |

规则（前缀 `pe`）：

1. `peTone`（8590）：表达倾向 = 松弛/紧绷（层级）+ `共情/分析/直接`（中心）+ 当前情绪 + MBTI。
2. `peSelfName`（8591）：`人设.自称` 非空且与顶层 `自称` 不同 → 写顶层 `自称`。
3. `peOwnerName`（8592）：`人设.对主人称呼` 同理。

**与 DSH 桥接的接口**：`plugins/dsh-astrbox/lib/astrboxService.mjs` 的 `PERSONA_PATHS` 固定读取
顶层 `种族/体型/毛色/自称/对主人称呼/人格.MBTI/人格.气质类型`。本层只**单向**把
`人设.自称/人设.对主人称呼` 同步到顶层，不反向写 `人设.*`；空值不覆盖旧数据。

## 4. 记忆闭环（`scripts/kernel/memory/`）

记忆内核原有短期/长期/情绪印记/遗忘/巩固保持不变，本次新增：

| 字段 | 含义 |
|---|---|
| `记忆.情绪印记源` | 最近一次情绪印记对应的情绪标签 |
| `记忆.印记效价` | 印记时刻的效价 |
| `记忆.关系记忆` | 关系类记忆通道（半衰期约 2 天） |
| `记忆.事件记忆` | 事件类记忆通道（半衰期约 1 天） |
| `记忆.自我记忆` | 自我类记忆通道（半衰期约 3 天） |
| `记忆.综合强度` | 五通道均值（长期、印记、关系、事件、自我） |

规则顺序（同一 tick）：`meMarkEvent/Relation/EventMem/Self`（8401–8404）先把
`情感.待印记/待记忆` 入账 → `meConsolidate`（8405）巩固 → 短期衰减（8410）→ 长期遗忘（8420）
→ 印记衰减（8430）→ 遗忘清零（8440）→ 回忆强度（8450）→ 通道衰减（8460）→ 综合强度（8470）。

**边界**：情感在 8523–8524 写请求，记忆在**下一 tick**消费（优先级 8401 < 8521），
所以「事件 → 印记」有 1 tick 延迟；这是刻意的，避免同一 tick 内读写顺序耦合。

## 5. 已知边界

1. **好感度不在本层**：`好感度/亲密/信赖/爱意/安全感/撒娇欲` 仍由 `关系` 实体持有（`relationModel.neko`），
   本层不跨实体写它；需要联动时由上层或后续多主体规则接入。
2. **类型 0 = 未设定**：未写 `九型.类型` 的实体不派生档案、不计算层级（保持默认 5）。
   侧翼是数据，规则不猜。
3. **无模板迁移**：新增字段靠模板回退可读；旧实体不会自动写实例，首次 tick 后才会写派生字段。
4. **部分组合**：只组合部分内核时，跨层读取按缺失处理（条件为 false、数值按 0），
   不要拿默认值当事实断言。
5. **人设路径是单向同步**：顶层 `自称/对主人称呼` 是桥接兼容路径，改顶层不会回写 `人设.*`。

## 6. 生效方式

- **新库/探针**：注册表为空时 `BootstrapFromSources` 扫描整个 `scripts/`，新增脚本自动注册。
- **已有 `data/scripts.json` 的运行库**：启动只 `ReplayAll` 已注册脚本，新文件不会自动注册。二选一：
  1. 用 MCP `neko_script_apply` 逐个应用：9 个新增脚本（`enneagramModel/Functions/Tick`、
     `emotionModel/Functions/Tick`、`personaModel/Functions/Tick`）+ 3 个修改过的记忆脚本
     （`memoryModel/Functions/Tick`）+ 1 个组合声明（`metabolismAttach.neko`）；
  2. 停服 → 备份 `data/scripts.json` → 把它移走或改名 → 重启，触发从 `scripts/` 引导；
     `data/scripts.json` 是派生索引，可重建（`docs/scripts-content.md` §4）。
- `make install-runtime` 只负责把 `scripts/**` 拷到 `~/.dsh-neko/Neko/scripts`，拷贝后仍需上面的注册步骤。
