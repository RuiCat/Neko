# 基础数据层定义（v1 草案）

> 状态：**定义稿，未冻结、未写脚本**。本文只定义字段、单位、默认值、范围、写入权与读取关系。
> 落地形态：`.neko` 模板（`@定义`），不改 Go 引擎。
> 日期：2026-11-14；基线 HEAD：`9805007`（工作树有未提交改动，以当前工作树为准）。

## 0. 名称与层级

- 本文所定义的层，按你的叫法称 **L1 基础数据**；为避免与 `docs/metabolism-architecture.md:24` 里已有的 **L1 生命轴（2000–2999）** 冲突，落地时的正式编号建议为 **B 层（基础数据层）**，取值 **500–899**。
- 既有号段全部保留、不重排：B 500–899 → 行为 900 → 代谢 L0 1000–1999 → 生命轴 L1 2000–2999 → 器官 L2 3000–3999 → 伤害 L3 4000–4999 → 生殖 L4 5000–5999 → 投影/状态 L5 9000–9999。
- 规则按 `优先级` **升序**执行（`docs/neko-semantics.md:76-77`），所以 B 层先于代谢，只写自己的组，不反向写代谢。
- 与代谢的关系：**同级底层、单向依赖**。基础数据是定义与静态参数，代谢是动态真值；代谢读基础数据，基础数据不读代谢。

## 1. 总原则

1. **一个字段一个所有者**：每个字段只有一个写入者；其余层只读。
2. **基础层只写三类**：`基础.*`（身份/体型/属性/派生）、`种族参数.*`、`器官基础.*`（静态账本）。
3. **`角色状态.*` 是底层定义的规范状态账本**：物理真值仍在代谢/循环/伤害；`角色状态.*` 由状态投影层单向派生写入，v1 不允许物理层反向读它（否则形成第二套真值）。
4. **单位整数化**：年龄=岁、身高=cm、体重=g、体温=0.1°C、心率=次/分、呼吸=次/分、比例=千分比（‰）、质量占比=万分比。
5. **不覆盖旧字段**：现有 `种族`/`体型`/`形态.性别`/`形态.体重`/`身体.*`/`状态.*`/`标记.*` 全部保留，作为兼容别名；新组一律用新顶层名，不侵入旧组。
6. **模板迁移不支持**（`docs/neko-semantics.md:53,190`）：新字段对已有实体通过模板回退可读；旧值靠一次性迁移写入。

说明：

- `基础.年龄` 是**整岁**，`基础.年龄分钟` 是岁内进度；两者共同表达连续年龄（1 岁 = 365×1440 = 525600 分钟）。默认 `自动增龄=false`，年龄不随时间变；打开后每 tick 累加 `流逝分钟`。
- `基础.年龄已知=false` 时视为“年龄未设定”：B 层**不推导** `性成熟`/`可孕`/`代谢修正`，保持模板默认值（`false`/`false`/`1000`），避免拿默认值冒充事实；设定年龄并置 `年龄已知=true` 后才派生。梦梦的 `年龄=0` 是真实婴儿年龄，需同时置 `年龄已知=true`。
- `基础.属性.*` 由“基准 50 + 种族修正 + 年龄修正”初始化（见 §4），之后允许宿主覆盖；不是每 tick 重算。
- `基础.特性` 是标签列表（如 `["猫耳","猫尾","肉垫"]`），只用于叙述/判定，不参与结算；与旧根字段 `特性`（对象）不同路径，不冲突。

## 3. 种族预设

五个预设键集完全一致；v1 的数值**刻意对齐现有脚本常量**（体温 368、心率 72、呼吸 14、代谢系数 1000），保证既有实测基线不变。种族生理差异先落在“类别/属性修正”，数值调参是后续独立决策。

| 种族 | 类别 | 成熟年龄 | 寿命 | 基础体温 | 基础心率 | 基础呼吸 | 代谢系数 | 孕期周 | 周期天 | 体型系数 | 生育上限 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 猫娘 | 猫科亚人 | 18* | 80 | 368 | 72 | 14 | 1000 | 40 | 28 | 1000 | 50 |
| 人族 | 人族 | 18 | 80 | 368 | 72 | 14 | 1000 | 40 | 28 | 1000 | 50 |

\* 成熟年龄 18 是**占位默认值**，不是世界观结论；由你确认后改（见 §8）。梦梦为婴儿，无论成熟年龄取多少，`年龄=0` 时 `性成熟=false`。

## 4. 派生定义（B 层初始化/增龄）

```text
若 年龄已知 == false：不派生 性成熟/可孕/代谢修正（保持默认 false/false/1000）
若 年龄已知 == true：
  性成熟 = 年龄 >= 种族参数.成熟年龄
  可孕   = 性成熟 ∧ 性别 ∈ {女, 双性} ∧ 年龄 <= 种族参数.生育上限

  年龄系数 = 未成年(< 成熟年龄) ? 1100
           : (年龄 <= 40)      ? 1000
           : max(800, 1000 - (年龄 - 40) × 5)

  代谢修正 = clamp(种族参数.代谢系数 × 年龄系数 / 1000, 500, 2000)
```

- `代谢修正` 的单位是千分比，1000 = 现有基线；L0 代谢在算“基础代谢 + 活动代谢”时乘 `基础.代谢修正 / 1000`，不改变 `代谢.基础代谢` 字段本身。
- **基线影响**：若角色年龄落在 18–40 岁，`代谢修正 = 1000`，L0–L5 实测值不变；若年龄 < 成熟年龄，`代谢修正 = 1100`（+10%），代谢基线会变——这是年龄语义带来的预期变化，需在验收时区分“定义错”还是“年龄设错”。
- v1 不把 `性别` 放进代谢公式（避免无依据的 ±5% 改动基线）；性别只驱动生殖/器官/属性修正。

增龄（默认关闭，打开后 600 段执行）：

```text
年龄分钟 += 流逝分钟
若 年龄分钟 >= 525600：年龄 += 1；年龄分钟 -= 525600
每次增龄后重算 性成熟 / 可孕 / 代谢修正
```

硬规则：

1. B 层不写 `代谢.*`/`循环.*`/`器官.*`/`伤害.*`/`生殖.*`。
2. L0–L4 不写 `角色状态.*`；`角色状态.*` 的派生值只由 L5 写。
3. 跨层需要回写时投递下一 tick 事件，不在同 tick 反向写（沿用 `docs/metabolism-architecture.md:32-33`）。
4. 一个字段只有一个写入者；新增写入者必须先改这份表，再改脚本。

## 7. 约束与校验（定义阶段）

1. **路径唯一**：`基础`、`种族参数`、`器官基础`、`角色状态` 四个顶层组在当前脚本与模板中均不存在（已核对 `scripts/` 与 `data/templates/`），不与旧组重叠。
2. **种族键集一致**：三个预设必须提供 §2.2 的全部 11 个键；缺键即视为定义不完整。
3. **类型固定**：物理量一律 int，不用 float；布尔只用 true/false；列表只用字符串列表。
4. **单位写作口径**：比例写“千分比（‰）”，质量占比写“万分比”；文档里的“1–100”都是整数刻度，不是百分比字符串。
5. **年龄双字段**：`年龄` 与 `年龄分钟` 必须同时存在；只写 `年龄` 时视为“岁内进度 0”。
6. **不引入新引擎能力**：全部用现有 `@定义`/`@函数`/规则能力；不需要 Go 改动。
7. **验收基线**：定义落地后（脚本实现阶段）以 `docs/metabolism-architecture.md:171-180` 的 L0/L1/L2/L3/L5 实测值为对照；年龄若在 18–40 且 `自动增龄=false`，数值应逐项不变。
