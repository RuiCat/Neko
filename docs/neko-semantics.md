# `.neko` 语义

> 本文描述**当前 Go 实现**的可观察语义。与旧文档冲突时，以本文和代码为准；文末列出已确认的差异与未实现项。

## 1. 模板与实体

### 1.1 模板来源

- `@定义` / `@定义` 声明实体模板；`@实例` 只声明数据，不进入实体模板；`@描述` 被忽略。
- 同一类型名可以被多个脚本重复声明。模板按 `DeepMerge` 合并：映射递归合并，标量和列表整体覆盖，**后应用的贡献覆盖先应用的**。
- 传统 `@定义` 类型仍按上述“后写覆盖”处理，不做字段级冲突检查；因此合并结果可能依赖脚本应用顺序。

### 1.2 `@实体` 组合

父模板由两部分组成，按顺序合并：

1. 类型名自带的冒号链（`角色基础:猫娘` 的隐式父 `角色基础`）；
2. `@实体 名称 [A, B]` 中显式声明的父，按声明顺序从左到右。

合并采用深度优先后序：先父、后子，子模板最后；同一祖先只合并一次（菱形去重）。

约束：

- **显式父必须存在**，否则拒绝；隐式冒号父缺失时容忍（兼容旧模板）。
- 组合关系成环 → 拒绝。
- 同一类型被多个脚本声明时：已注册父列表非空时，新的**非空**父列表必须与之一致；空父列表的后续声明不会覆盖已注册的父列表。
- 同一脚本内重复声明同一类型且父列表不一致 → 编译错误。

字段约束是**严格单所有者**：

- 子模板自己的字段**不得与任何祖先字段重叠**（包括“标量 vs 嵌套对象”的前缀重叠）；
- 两个祖先之间**不得有同路径字段**，即使值相同；
- 同一 `@实体` 类型的多个贡献之间不得重复定义同一路径。

也就是说，`@实体` **不支持子覆盖父**。组合的用法是“把互不重叠的能力字段拼成一个类型”，不是“子类改写父类默认值”。

被组合类型在参与选择器匹配时，祖先类型名会作为派生标签加入匹配；因此 `@规则[$[父类型]]` 会自动作用于组合类型。

### 1.3 注解

- 模板的 `__annotations__` 参与模板合并；schema 按组合顺序构建。
- 注解按字段逐项继承：子模板为同一路径写了 `type`/`event`/`min`/`max` 等约束时覆盖父模板，未写的项从父模板继承（`EntitySchema.MergeInherited` / `FieldSchema.MergeInherited`）。
- `@实体` 因字段严格不重叠，同一路径只有一个来源，通常不会遇到注解覆盖问题。

### 1.4 实体创建与读写

- 创建实体时，按组合顺序合并模板，再用创建参数里的 `data` 覆盖；`ID` 不允许 `.`、`[`、`]`、空格。
- 模板元数据（`__annotations__`、`__parents__`）不会复制进实例 `data`；加载旧实体文件时也会在内存里剥掉，下次保存即清理。
- 读取路径时先查实例 `data`；缺失时按“自身 → 父（逆合并顺序）”回退到模板。
- 写入路径会按需创建中间映射；写入成功后触发 `OnChange`。
- `@事件` 的 schema 校验失败只记录诊断，**不会阻止写入**。
- `readonly` 注解在 `Entity.Set` 处强制拦截：写入返回 `ValidationError`，不触发 `OnChange`。
- 实体创建后不会因模板变化自动重算。已有字段保持实例值；模板新增字段可以通过回退读取看到。**当前没有模板变更迁移机制**。
- 删除仍被其它模板声明为父的脚本会被拒绝（依赖检查），不会留下悬空父引用。

### 1.5 选择器与查询

- `ID`、`TYPE[ID]`、`TYPE[*]`、`[*]`。
- 类型匹配同时接受**子类型前缀**和实体 `分类` 字段里的标签。
- 查询支持 `key:键=值` 和 `字段=值` 形式（见 MCP 工具文档）。

### 1.6 模板声明与运行时写入

- **严格单所有者只约束模板字段声明**：`ValidateComposition` 检查的是模板贡献的路径，不检查实体运行时的写入路径。
- 事件处理器、`@函数` 和规则动作写的是实体状态，可以写当前实体上的任意路径，包括祖先模板声明的字段；写入时按需创建中间映射（§1.4）。
- 子模板的行为要“挂到”父字段上时，有两种合法做法：
  1. 子模板声明自己的触发字段（如 `猫耳.被摸[@抚摸猫耳]`），由字段事件触发处理器；
  2. 用 `@规则[$[子模板]]`，祖先类型名作为派生标签参与匹配（§1.2），规则里直接读写父字段。
- 在 `@实体` 组合中，子模板**不能**给父模板已有字段补注解或改默认值；这属于模板声明修改，受严格单所有者限制（§1.2、§9）。传统 `@定义` 的冒号链目前仍不启用严格校验（字段级冲突检查只作用于声明了父列表的组合类型），不属于本节说的“绑定”。
- `@事件` 体的动作行只解析不执行（§5），行为必须写在 `处理器:` 指向的 `@函数` 里；处理器写父字段时，如果父字段本身带 `@事件` 注解，会继续触发对应事件，注意递归。
- 数据所有权：本仓库基础数据层采用“一个字段一个所有者”（`docs/base-data-definition.md` §1）。特征模板直接写父层字段会使它成为第二写入者；推荐特征只写自己的输入字段，由父层规则派生目标字段，或在设计上明确该字段为多写入者交互账本。

## 2. 规则与状态机

### 2.1 规则编译

- 主语决定 `match`：`$` → `[*]`，`$[角色基础]` → `角色基础[*]`，全局实体 → 实体 id。
- `条件:` / `状态:` / `分支` 的条件会做编译期重写（见第 3 节），多个条件以 `∧` 连接成 `when`。
- 没有分支时：有动作则生成一个无条件分支；没有动作则生成 `else` 空分支。
- 规则 id：显式 `id:` 优先，否则用匹配条件与动作内容生成哈希。
- 注册时同 id 的规则替换；同签名（match/priority/when/then 相同）的启用规则会被去重。

### 2.2 Tick

- 只执行 `Enabled` 的规则。
- 规则按 `Priority` **升序**稳定排序：数值小的先执行，数值大的后执行。
- `scope` 为空或无法解析时执行全部实体；可解析时只处理匹配实体。
- 预算：单次 Tick 最多评估 3000 条规则；每条规则最多 2000 次转移。
- 多主体规则对主体选择器做笛卡尔积；同一实体重复出现的组合会被跳过；`scope` 只过滤第一个主体。
- Tick 只改内存；是否落盘由调用方（如 `run_tick` 工具）决定。
- 同一 Tick 内，相同“实体 + 路径 + 值”的操作只应用一次。

### 2.3 分支与冲突

- 分支从上到下短路：`If` 为真即命中；空 `If` 视为无条件；`Else` 兜底。
- 没有命中任何分支且没有 `else` → `no_branch_match` 冲突。
- 同一 Tick 内不同规则把同一个已声明的状态组写成不同值 → `branch_race` 冲突（仅对 `状态定义` 中声明过的组）。
- 冲突进入待仲裁队列，可用 `state_machine_resolve` / `ResolveConflict` 写入目标状态，并记录决策日志。

## 3. 条件

编译期：

- 单主体 `$[类型].x`、`$.x` 重写为 `{e}.x`；`$` 重写为 `{e}`。
- 裸字段按 `BareFieldMap` 补全；未命中时默认挂到 `身体`。
- 比较表达式右侧的裸中文路径字段在 `>` / `>=` / `<` / `<=` 场景也会补全为 `{e}.身体.X` 或映射表路径。
- `场景` / `世界` / `时间` / `天气` / `全局` 等全局实体引用保持原样。
- 多主体 `$1` / `$2` 引用保留，由运行时绑定。

运行期：

- 路径无法解析时按 `false` 处理，不中止整个表达式。
- 支持 `∧`/`and`、`∨`/`or`、`!`/`~`、括号、比较、`in`、`contains`。
- 右侧 `{a,b,c}` 是集合字面量，配合 `in` / `==` / `!=` 使用。
- 数值比较会做数值化；非数值按字符串比较。
- 支持算术操作数（`+ - * / %`、括号、数字、路径、字符串），除数为 0 时该操作数不可解析。
- 规则条件里可以调用 `@函数`（`函数名(参数...)`），由函数执行器求值。
- 事件条件额外支持 `变化量`、`旧值`、`新值`、`实体`、`字段`。

## 4. 动作

- 目标：`$` / `$N` / `$.路径` / `$N.路径` / `{e}.路径` / 全局实体.路径 / 裸路径。
- 操作：
  - `=` → `set`
  - `+=` / `-=` → `add`（数值相加；右侧是容器或目标为全局实体时在解析阶段转为追加）
  - 编译结果还支持 `append` / `emit`
- `set` 会按模板注解的 `min` / `max` 做限幅。
- `append`：目标不是列表时先当成空列表；写入场景事件字段时按 `scene_event_limit`（默认 50）保留最新条目。
- `emit`：把事件追加到场景的事件列表；未指定场景时落到 actor 的 `位置.场景`（可配置）。
- 动作值支持：
  - 字面量（字符串、数字、布尔、JSON 容器）
  - `$路径` 运行时引用；`$.路径` 归一为当前实体，`$N.路径`（$1/$2）按多主体绑定解析
  - 拼接表达式与 `函数名(...)` 调用
  - `&{字段}` 形式的占位符
- `set` 的字符串值如果包含 `@效果:` / `效果+数值` 等文本，会触发 `applyTextEffects` 的附加写入（与 Python 版兼容行为）。
- `分支` 的 `状态 = "x"` 是写入状态组默认子组的语法糖。

## 5. 事件

- 字段注解 `@事件名` 把路径绑定到事件；写入该路径时由事件桥触发。
- 事件定义：`条件:`、`处理器:` / `处理:` / `handler:`；没有处理器时默认用事件名。
- 条件在事件上下文中求值，支持 `变化量`、`旧值`、`新值`、`实体`、`字段`。
- 处理器以**变化量**为唯一参数调用，当前实体作为相对路径的解析上下文。
- 同名事件被多个脚本定义时，**带条件**的定义优先于无条件定义。
- 事件处理的写入会再次触发字段事件；嵌套受函数调用深度（20）和执行步数（100000）限制。
- 同一时刻最多 256 个事件在途；超过时记录警告并拒绝本次派发。
- 事件历史保留最近 128 条。
- `@事件` 体里的动作行目前会被解析进 `EventDef.Actions`，但**事件总线只执行处理器，不执行这些动作行**。

## 6. 函数

- `@函数` 注册后可被规则条件、动作值和事件处理器调用；同名重复注册会替换。
- 参数按位置绑定；缺参填 `nil`，多余实参忽略。
- 调用深度上限 20；单次调用执行步数上限 100000。
- 局部变量：直接赋值裸名 `x = 1` 写局部变量；带点路径写实体字段。
- 路径根解析顺序：
  1. 局部变量（若变量的值是实体 id，则继续按实体读；若是 map，则按 map 读）；
  2. 同名实体 id；
  3. 当前实体。
- 写入目标解析顺序类似；根既不是局部实体 id 也不是实体 id 时，写入当前实体的同名路径。
- 真值规则：`nil`、`false`、`0`、`""`、空列表、空映射为假。
- 运算符：`+` 支持数字/字符串/列表；`*` 支持字符串/列表重复；`-` / `/` / `%` 只接受数值；类型不符报类型错误。
- 比较支持链式；`in` / `contains`；`and` / `or` 短路。
- 内置函数：`int`、`float`、`str`、`len`、`abs`、`round`、`min`、`max`、`range`、`enumerate`、`zip`、`sum`、`sorted`、`reversed`、`随机`；`print` 是空操作。
- 方法：列表 `append/extend/insert/remove/pop/clear/count/index/sort/reverse`；文本 `format/join/split/...`；映射 `keys/values/items/get/update/setdefault/copy`（完整清单见 `docs/neko-script.md`）。
- `for` 可遍历列表、文本（按 rune）、映射（按键排序后的键）；`while` 受步数上限约束。
- `try/except` 按错误种类匹配：`值错误`、`类型错误`、`名称错误`、`错误`（以及对应英文名）；`except e` 绑定错误消息；`finally` 总会执行。
- 无 `返回` 时函数返回 `nil`。
- `continue` 只有英文写法。

## 7. 脚本注册与生命周期

- 应用脚本：逐块解析（单块失败不影响其它块）→ 编译 → 模板组合校验 → 提交。
- 模板校验在 `commit` 之前执行；失败不落盘。
- 相同 hash 且未 `force` 时不重复应用。
- 提交时：模板 `DeepMerge` 进 store、写 `data/templates/<名称>.json`（`@实体` 另写 `<名称>.parents.json`），规则进引擎，函数/事件注册；`scripts.json` 记录引用计数。
- 删除脚本：按引用计数释放模板/规则；仍有其它模板引用被删模板作为父，或仍有冒号前缀子类型时，拒绝删除。
- 启动时按脚本名的字典序重放（`BootstrapFromSources` 与 `ReplayAll` 都先排序）；注册表缺失时从 `scripts/` 递归引导。
- 重放只恢复内存状态，不回写 `scripts.json`；模板文件与实体文件不因重放自动迁移。
- 脚本应用顺序会影响传统 `@定义` 的同名覆盖结果；`@实体` 组合顺序由父列表决定，不依赖脚本顺序。

## 9. 语义决策与已实现约束

以下五项曾是「未实现/差异」，2026-11-16 复检后分成两类：

**已实现（本轮）**

- **`readonly` 拦截写入**：模板注解 `readonly` 在 `Entity.Set` 处强制生效，写入返回 `ValidationError`（回归：`internal/entity/readonly_test.go`）。
- **`@事件` 动作行编译告警**：事件体里的动作行不会被执行成副作用，编译期现在明确告警「请改用 `@函数` 处理器」，不再静默忽略。

**设计决策（保持现状，不是缺陷）**

- **模板迁移**：模板默认值/父变更不重写已有实体数据；新增字段由模板回退自然生效，删除字段保留实例旧值。推翻条件：需要批量改档时，另做显式迁移工具（带 dry-run 与备份），不做自动迁移。
- **删除父模板被拒绝**：依赖检查优先于自动迁移；删除前必须先解除依赖（改子模板父列表或删依赖方）。推翻条件：出现「迁移后删除」的真实需求。
- **`@实体` 不允许子覆盖父**：组合类型严格单所有者，子实体 body 与父模板同路径即报错；示例需保证字段互不重叠。推翻条件：确需覆盖时改契约（显式 `覆盖` 声明），不能静默放宽。

近期已修正、不再列为差异：

- 优先级方向统一为**升序**（数值小的先执行），`docs/neko-script.md` 已同步。
- 注解按字段逐项继承：子模板未写的 `type`/`event`/`min`/`max` 从父模板继承；`clampValue` 也按祖先链继承 min/max。
- 实例数据不再复制 `__annotations__` / `__parents__`，加载旧数据时会在内存中剥离。
- 事件深度文档已改为当前实现：函数调用深度 20、执行步数 100000、在途事件 256。
