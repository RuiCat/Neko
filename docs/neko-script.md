# `.neko` 脚本语言

`.neko` 是 AstrBox 的块级脚本方言，用来声明实体模板、状态机规则、字段事件与函数。文件按 UTF-8 文本读取，`//` 与行首 `#` 为注释。

完整 EBNF 语法见 [neko-grammar.md](neko-grammar.md)。

语义（模板合并、规则匹配、条件/动作求值、事件与函数执行限制）见 [neko-semantics.md](neko-semantics.md)。

## 顶层块

| 块 | 形式 | 产物 |
|---|---|---|
| 实体模板 | `@定义 角色基础:猫娘 { ...JSON... }` | 模板 `角色基础:猫娘`（注解在此展开） |
| 组合模板 | `@实体 角色基础:猫娘 [角色基础, 猫耳, 猫尾, 肉垫] { ...JSON... }` | 模板 `角色基础:猫娘` + 父列表 |
| 数据实例 | `@实例 类型:修饰:…:名称 { ...JSON... }` | 不编译为模板，由 `neko-data apply` 物化成实体 |
| 规则块 | `@规则[...] { ... }` | 一条或多条规则 |
| 行式规则 | `#规则: 条件 → 动作` | 一条规则 |
| 事件 | `@事件 名称 { 条件: ... 处理器: ... }` | `EventDef` |
| 函数 | `@func 名称(a:int, b:int):int { ... }` | `FuncDef` |
| 元数据 | `#世界观: ...` | 元数据（不参与执行） |

`@定义` / `@实例` 的块体必须是合法 JSON；解析失败会记录错误，但同一文件里的规则仍会被应用
（fail-soft，与 Python 版一致）。

> **关键字只有两套**：`@定义` / `@实体` 建模板，`@实例` 建数据实例。
> 大小写不再有语义——旧的 `@Data` / `@data` 已移除，写成它们会**直接报错并给出替代写法**，
> 而不是静默变成另一种块；任何未知的 `@关键字`（如 `@dta` 拼错）同样在解析期报错。

> **命名约定：冒号段是限定，最后一段在内容层是实体 id。**
>
> `角色基础` 是完整的基础角色定义（组合全部内核），不带种族特征时**默认就是人族**。
>
> - 模板（类型）：`@实体 角色基础 [基础内核, …, 任务状态] {}`、`@实体 角色基础:猫娘 [角色基础, 猫耳, 猫尾, 肉垫] {}`
> - 实例（数据）：`@实例 角色基础:猫娘:猫猫 { … }`（类型 `角色基础:猫娘`、id `猫猫`）
> - `@实例 角色基础:小海` 也合法，含义是「小海是人族」。
>
> 种族是**组合**出来的（基础 + 特征模板），不是从人族继承的特例；任意「基础 + 若干特征」都成立。
> 详见 [scripts-content.md](scripts-content.md)。

## 组合模板 `@实体`

`@实体` 用方括号声明父模板，组合成一个新类型。block 体仍是 JSON 字段；父列表用空格与类型名分隔，`extends` 不是必需关键字：

```neko
@定义 角色基础:猫科 { "毛色": "未知" }
@定义 角色基础:成年 { "年龄": 18 }

@实体 角色基础:猫猫 [角色基础:猫科, 角色基础:成年] {
  "体型": "幼"
}
```

规则：

- **严格单所有者**：一个类型的每个叶子路径只能由一个模板定义。父与父之间、子与父之间出现同一路径（即使值相同）都会报错；子模板**不能**覆盖父模板的默认值。
- 父模板必须存在；父列表缺失、重复、循环依赖都会报错。同一脚本内可以同时声明父与子；跨脚本时父脚本需要先 apply/先注册（bootstrap 按脚本名排序）。
- 冒号链仍然有效：`@实体 A:B:C [X]` 会先合并 `A`、`A:B`，再合并 `X`，最后合并自己的字段；同样要求字段不重叠。
- 应用脚本时校验，校验失败不落盘、不注册。删除脚本时，如果仍有模板把即将删除的类型声明为父（或通过冒号链依赖它），删除会被拒绝。
- 父列表持久化在 `data/templates/<类型名>.parents.json`；模板本体仍在 `<类型名>.json`。实体读取回退与 schema 都按组合祖先顺序解析。
- 传统 `@定义` 同名多脚本贡献仍保持“后写覆盖”的旧行为；严格校验只作用于声明了父列表的组合类型，便于旧脚本渐进迁移。

> 当前版本不对已有实体做自动迁移（设计决策）：改默认值只影响之后新建的实体，已有实体保留实例数据；新增字段通过模板回退生效。需要批量改档时使用显式迁移工具（尚未提供），不做隐式重写。

### 组合与行为：子模板可以写父字段

严格单所有者约束的是**模板字段声明**，不是运行时写入。组合后的实体是一个整体：子模板声明的事件处理器、`@函数`、规则动作都可以写父模板声明的字段。

```neko
// 假设父模板 角色基础 已声明 感觉 / 感情
@定义 猫耳 {
  "猫耳": {
    "灵敏[int,min:0,max:100]": 50,
    "被摸[int,min:0,max:100,@抚摸猫耳]": 0
  }
}

@函数 猫耳被摸(变化量:int) {
  {e}.感觉.舒服 = {e}.感觉.舒服 + {e}.猫耳.灵敏 / 10
  {e}.感情.亲密 = {e}.感情.亲密 + 1
}

@事件:抚摸猫耳 {
  条件: 变化量 > 0
  处理器: 猫耳被摸
}
```

- **触发字段必须由某个模板声明**：在 `@实体` 组合中，子模板不能给父模板的字段补 `@事件` 注解；那属于修改父模板声明，严格单所有者会拒绝。
- **事件体里的动作行不会执行**：必须走 `处理器:` + `@函数`（见 [neko-semantics.md](neko-semantics.md) §5）。
- **持续/条件式行为**也可以用 `@规则[$[猫耳]]`：祖先类型名会作为派生标签参与匹配（见 [neko-semantics.md](neko-semantics.md) §1.2）。
- **数据层仍建议“一个字段一个写入者”**：子模板最好写自己的输入字段，再由父层派生；直接写父字段会让子模板成为第二写入者。

## 规则主语

规则头用方括号选择作用对象：

```neko
@规则[$[角色基础]]    { ... }   // 全部角色的实体，match = "角色基础[*]"
@规则[$]             { ... }   // 全部实体，match = "[*]"
@规则[场景]          { ... }   // 全局实体「场景」
@规则[$1[角色基础]，$2[角色基础]] { ... } // 多主体，$1/$2 在动作里交叉绑定（逗号必须是全角 `，`）
@规则[角色基础.性别=女] { ... }   // 带属性条件
```

单主体规则里，`$` 与 `$[类型]` 在编译期重写为 `{e}`（当前实体）；多主体的 `$1`/`$2` 保留，由引擎按笛卡尔积绑定。

> 多主体规则头的分隔符是**全角逗号** `，`：`internal/neko/parserRule.go` 只按 `，` 切分，用 ASCII `,` 会把后面的主体并进类型名。
> 多主体条件里不要用括号分组的 `∨`（`(A ∨ B)` 不成立），需要二选一时拆成两条规则。

## 规则体

```neko
@规则[$[角色基础]] {
  id: r_thirst              // 可选，缺省用内容哈希
  优先级: 10                // 可选，数值越小越先执行
  状态: 状态.身体 = "活跃"   // 可选，作为 when 的一部分
  条件: 身体.水分 < 20
  动作: 状态.身体 = "口渴"
      标记.口渴 = true
  分支: {
    身体.体力 < 10 → 状态 = "昏厥"
    身体.体力 < 20 → 状态 = "疲惫"
    默认 → 状态 = "活跃"
  }
}
```

- `条件` / `状态` 参与 `when`；多个条件用 `∧` 连接。
- `分支` 从上到下短路，第一个命中生效；`默认` 为兜底。
- 分支行 `状态 = "昏厥"` 是语法糖，编译为 `state: {"身体": "昏厥"}`；`状态.情绪 = "难过"` 写入 `情绪`。
- 只有分支没有条件时，分支的 `if` 即条件；分支和动作都为空时编译报错。

### 条件表达式

支持 `∧`/`∨`、`!`、括号、比较（`= == != > >= < <=`）、`in`、`contains`、集合字面量、路径引用与函数调用。

裸字段会被补全到正确分组：

```neko
体力 < 10            → {e}.身体.体力 < 10
主人行为 in {抚摸}    → {e}.行为.主人行为 in {抚摸}
疼痛 > 95 ∨ 出血 > 70 → {e}.状态.疼痛 > 95 ∨ {e}.伤害.出血 > 70
```

裸字段到分组的映射表在 `internal/compiler/rewrite.go` 的 `BareFieldMap`；未命中时默认挂 `身体`。`场景`/`世界`/`时间`/`天气`/`全局` 开头的引用保持原样。

### 动作

| 写法 | 编译结果 |
|---|---|
| `状态.身体 = "疲惫"` | `{"op":"set","path":"{e}.状态.身体","value":"疲惫"}` |
| `身体.体力 += 5` | `{"op":"add","path":"{e}.身体.体力","value":5}` |
| `身体.体力 -= 5` | `{"op":"add","path":"{e}.身体.体力","value":-5}` |
| `场景.事件 += "下雨"` | `{"op":"append","entity":"场景","path":"事件","value":"下雨"}` |
| `$1.亲密 += 5` | `{"op":"add","subject":1,"path":"亲密","value":5}` |
| `{e}.标记.疲劳 = true` | 原样路径 |
| 动作值 `体力`（裸路径） | 编译为 `$体力` 引用，运行时解析 |

字符串必须加引号；裸路径（形如 `a.b.c`）会被当作引用，数字/布尔保持字面量。

**`场景` 是「当前场景」，不是写死的实体**：`场景.事件 += ...` 编译出的 `entity:"场景"` 在运行时
由引擎解析——库里真有 id 为 `场景` 的实体就用它，否则落到 actor 的 `位置.场景`（`current_scene_path`
可配）。所以同一条规则对「猫猫在客厅」「梦梦在卧室」分别写进各自场景。`emit` 同理（未指定场景时
落到当前场景）。场景事件列表按 `scene_event_limit`（默认 50）截断，事件黑板只投影最新一条
（`事件.最新`），推送不会搬整份历史。示例见 [docs/examples/scene_events.neko](examples/scene_events.neko)。

**`在场` 由引擎自动维护**：每 tick 结束时按所有实体的 `位置.场景` 重算场景实体的 `在场`
（实体 id 列表，按 id 排序），位置没变就不写。脚本可以读它（例如判断「这个场景里还有谁」），
但**不要手写 `在场`**——下一次 tick 会按真实位置覆盖。

### 行式规则

```neko
#规则: 身体.体力 < 20 → 状态.身体 = "疲惫"
```

`→` 左侧是条件，右侧是动作；适合一行能表达的小规则。

## 字段注解

`@定义` 的 JSON 键可带注解，用于默认值、类型、事件与范围：

```neko
@定义 角色基础 {
  "身体": {"体力[int,@体力管理,min:0,max:100]": 75}
}
```

编译展开为字段 `体力 = 75` 与注解表：

```json
{"身体.体力": {"type": "int", "event": "体力管理", "min": 0, "max": 100}}
```

支持的类型/约束：`int` `float` `str` `bool`、`@事件名`、`enum:a;b;c`、`min:N`、`max:N`、`readonly`、`nullable`。子类模板覆盖字段时，未写的注解从父类继承。

## 函数与事件

```neko
@func 加(a:int, b:int):int {
  返回值 a + b
}

@事件 状态变化 {
  条件: 变化量 > 0
  处理器: onStateChange
}
```

Go 版已接入函数执行器与事件总线：字段注解绑定的事件在写入时触发，条件可用 `变化量`/`旧值`/`新值`，处理器是同名或 `处理器:` 指定的 `@函数`。嵌套受函数调用深度 20、单次调用执行步数 100000、同一时刻在途事件 256 共同限制。

`@函数` 支持变量、`if/else if/else`、`while`、`try { ... } except 错误 { ... } finally { ... }`（可写 `except 值错误 as e` 按类型捕获）、`break`/`continue`、`返回`、`for 项 in 列表/文本/映射`、`for i, v in enumerate(...)`、元组赋值 `a, b = 1, 2`、map 字面量 `{"键": 值}`、字符串拼接、切片（含步长 `[a:b:c]`）、链式比较（`1 < x < 5`）、`int()`/`float()`（非法输入报错）、`in`/`contains`、函数互调，以及常用方法：列表 `append/extend/insert/remove/pop/clear/count/index/sort/reverse`，文本 `format`（`{}`/`{0}`/`{:.2f}`/`{:>5}`/`{!r}`）/`join/split/rsplit/strip/replace/lower/upper/startswith/endswith/find/rfind/index/rindex/count/partition/removeprefix/removesuffix/title/capitalize/casefold/expandtabs/isdigit/isalpha/isnumeric/isalnum/isspace/islower/isupper/istitle/isascii/isprintable`，映射 `keys/values/items/get/update/setdefault/copy`；支持列表推导 `[x for x in ... if ...]` 与 `range/enumerate/zip/sum/sorted/reversed`；内置 `随机(a,b)` 返回 `[min(a,b), max(a,b)]` 内的随机整数。对当前实体（`状态.身体`）和变量绑定实体（`素材.所属场景`）的读写同样可用。

## 解析与错误

`internal/neko.Parse` 逐块解析并 fail-soft：单个块的错误进入 `ScriptAST.Errors`，不影响后续块。注册表会把这些错误作为 warning 返回，但继续应用可解析的规则。
