# 从旧脚本备份补全实现：规划分析

> 对象：`/home/ruicat/Desktop/备份/scripts`（旧语料，198 个 `.neko`、约 1.1 MB、10 个子目录）。
> 原则：**以当前内核为基础补全**，不整包导入旧规则；旧语料只作为「能力清单 + 数据/字段来源」。
> 私有角色（猫猫/梦梦）数据与公共定义分开存放。

## 1. 结论

1. 旧语料是**功能完整但模型不兼容**的上一代实现：规则按旧字段名写死，字段是「一个文件一个 `@定义`」的增量拼装；
   当前是「内核模板 + 组合」模型。整包导入会造成双写、字段冲突和优先级打架，**必须按能力域提取**。
2. 旧语料真正值得搬的是三类：
   - **公共实体定义**（内容）：行为模板库、任务模板库、性行为流程库/事件整理、示例素材（花）、场景资产；
   - **内核定义**（缺失的状态子系统）：人格、成长、好奇心、社交、环境感受、表情、对话偏好、记忆补充、触觉；
   - **私有角色数据**：`角色基础:猫猫` / `角色基础:梦梦` 的角色专有字段。
3. 旧语料里的**规则/函数不复用**：当前 L0–L11 内核已覆盖生理/伤害/生殖/物品/交互/认知，旧规则依赖旧字段，
   搬进只会制造第二写入者。

两个格式障碍（抽取器必须处理）：

1. **块体内有 `//` 注释**（如 `行为模板` 的「食物链」分隔行）→ 不是严格 JSON，`json.Unmarshal` 直接失败；
2. **键带注解**（`"体力[int,@体力管理,min:0,max:100]"`、`"饱腹[int,@饱食管理,...]"`）→ 抽成实例前必须去掉 `[...]`，
   事件注解 `@xxx` 也不属于实例数据。

## 4. 目标目录（在现有分层上扩展）

```text
scripts/
  kernel/                      # 内核定义（注册为脚本）
    ...                        # 现有 L0–L11
    library/libraryModel.neko  # @定义 资料库（名称/类别/条目）——承载各类模板库
    personality/               # 人格内核（大五 + MBTI + 气质）
    growth/                    # 成长内核（经验/等级/上限）
    curiosity/                 # 好奇内核（探索/已探索场景/最近发现）
    social/                    # 社交内核（互动需求/主人互动/孤单）
    environment/               # 环境感受内核（季节/天气偏好与感受）
    expression/                # 表情内核（可选）
  entities/
    characters/                # 公共角色（非私密）
    items/                     # 公共物品（花等）
    foods/
    library/                   # 公共资料库数据：任务模板库/行为模板库/性行为流程库/事件整理
  scenes/                      # 场景内容
  private/                     # 私有（.gitignore）：猫猫/梦梦 数据、私有人设/称呼
```

- `private/` 与 `entities/`、`scenes/` 一样**不注册为脚本**（`CONTENT_DIRS` 扩展），只由 `neko-data apply` 物化；
  默认应用范围 = `entities` + `scenes` + `private`（存在才读）。
- 私有模板不再需要：角色实例直接用公共类型，块名写成 `@实例 角色基础:猫娘:猫猫 { ...旧模板字段... }`，字段按当前内核分组命名。
  （旧写法 `@实例 角色基础:猫猫` 会解析成裸类型 `角色基础`，丢掉种族，已废弃。）

工作量粗估：P0+P1 半天；P2 一天；P3 半天；**P4 两天以上**（旧 197 条行为流程的语义需要逐条映射到新内核字段）。

## 6. 风险

1. **P4 是主要成本**：旧行为模板是「脚本命令 + 字符串步骤」，新模型需要结构化的前置条件和效果；逐条迁移需要人工判断。
2. **数据与引擎解耦期**：P3 抽进来的资料库在执行引擎完成前只是数据，不会让角色真的「去买菜」。
3. **字段冲突**：旧 `角色基础` 增量模板里的组名（如 `状态`/`清洁`/`记忆`）与当前内核组名可能重名，抽取时要显式映射，冲突项报告不合并。
4. **隐私泄漏**：`private/` 不进版本库，但**整仓备份会把 private 一起打包**；备份脚本需要加排除或单独加密，P0 必须处理。
5. **旧规则不回移**：抽取只搬模板/数据；旧 `@规则` 里的阈值/映射若需要，按当前内核重写，不复制。
