# 代谢底层分层脚本架构（v1）

> 本文件是 `.neko` 脚本层的**分层契约**：谁先算、谁写哪个字段、用什么单位、怎么验收。
> 旧脚本（`scripts/` 已清空）按本文重建；本文先行冻结，脚本逐层实现。

## 1. 已冻结的决策

| 项 | 决策 |
|---|---|
| 重写边界 | 只重写 `.neko` 脚本层；Go 引擎不动，除非语法/执行器缺口阻断 |
| 内核形态 | 代谢是独立模板 `代谢内核`；角色用 `@实体 NPC [代谢内核]` 组合，不寄生在 NPC 定义里 |
| 旧脚本 | 全部作废，从零重建（`git HEAD` 仅作行为参考） |
| 数值单位 | 物理量整数化：kcal、mL、0.1°C、mmHg、mg/dL、g |
| 分层方式 | 规则 `优先级` 升序执行（**数值小的先跑**，`internal/engine/engine.go:190` 实证） |
| 方向 | 代谢是唯一底层真值；上层只读它，投影层负责 0–100 玩家可见刻度 |

## 2. 分层与优先级带

规则按 `优先级` **升序**执行；同优先级按注册顺序（稳定排序）。每层占用独立号段，层内留 10–90 的步进余量。

| 层 | 号段 | 职责 | 只读 | 只写 |
|---|---|---|---|---|
| L0 代谢 | 1000–1999 | 能量、体液、电解质、体温 | 摄入/活动/环境输入 | `代谢.*` |
| L1 生命轴 | 2000–2999 | 心率、血压、灌注、氧合、激素相位 | `代谢.*` | `循环.*` `呼吸.*` `内分泌.*` |
| L2 器官账本 | 3000–3999 | 完整性、功能储备、修复 | L0/L1 | `器官.*` |
| L3 伤害引擎 | 4000–4999 | 屏障、破口、出血、污染、缺血 | L0–L2 | `伤害.*` |
| L4 生殖与性 | 5000–5999 | 周期、受孕、怀孕、性反应、路径 | L0–L3 | `生殖.*` `性.*` |
| L5 派生与投影 | 9000–9999 | 0–100 刻度、状态词、标记 | 全部 | `身体.*` `状态.*` `标记.*` |

**硬规则**：

1. 跨层只读不写：L1 不得写 `代谢.*`，L2 不得写 `循环.*`。
2. 需要回写上游时，投递到下一 tick 的事件，不在同 tick 反向写。
3. 投影层（L5）是唯一允许写 `身体.体力/饱食/水分` 的地方——旧脚本各写各的，正是冲突来源。
4. 每个字段在 `docs/metabolism-architecture.md` §4 有唯一归属者。

## 3. 单位约定

| 物理量 | 字段单位 | 说明 |
|---|---|---|
| 能量 | kcal（整数） | 储备、摄入、消耗同单位 |
| 液体 | mL（整数） | 体液 42000、血液 5000 |
| 温度 | 0.1°C（整数） | 368 = 36.8°C |
| 血压 | mmHg（整数） | L1 使用 |
| 血糖 | mg/dL（整数） | 90 正常 |
| 糖原/蛋白 | g（整数） | |
| 电解质 | mmol/L（整数） | |
| 时间 | 分钟（整数） | `代谢.流逝分钟` 由宿主写入 |

**tick 长度无关性**：所有速率都乘 `代谢.流逝分钟 / 1440`（日速率）或 `/ 60`（小时速率），不允许假设 1 tick = 1 分钟。

## 5. 结算公式（S0）

```text
吸收   = 胃内容 × 流逝分钟 / 240          // 约 4 小时排空
消耗   = (基础代谢 + 活动代谢) × 流逝分钟 / 1440
能量储备 += 吸收 − 消耗
胃内容   −= 吸收
血糖      += 吸收 / 20 − 2×流逝分钟/60     // 吸收升糖、基础消耗降糖
体液     += 摄入液 − (尿量 + 出汗 + 800×流逝分钟/1440)
血液      = 体液 / 8
产热      = 消耗
散热      = (体温 − 环境温) × 流逝分钟 / 120 + 出汗 × 3
体温     += (产热 − 散热) / 40
体力      = 能量分×40 + 血糖分×20 + 体液分×20 + 体温分×20（各自 0–100）
饱食      = 胃内容 / 1500 × 100
水分      = 体液 / 42000 × 100
```

## 8. 迁移（现有实体获得新字段）

`@定义` 只影响**新建实体**。已在库的 `猫猫/梦梦` 需要一次性写入默认值：

```text
neko_script_apply → 注册脚本
entity_state_set(猫猫, values={代谢: {...默认值...}})
entity_state_set(梦梦, values={代谢: {...默认值...}})
```

或用 `entity_create` 重建实体（会丢历史数据，不推荐）。

## 9. 与旧脚本的关系

旧脚本的 `身体.体力/饱食/水分` 由多条规则各写各的（`cat_body_state`、`cat_core`、`cat_behavior` 等），互相覆盖。
新架构下这些字段**只有投影层写**，其余脚本一律读 `代谢.*`。旧脚本不恢复，按层重建。


## 10. 引擎实测约束（探针结论）

用 `.local/probe`（编译 → 注册 → 建实体 → tick）实测得到，写新脚本必须遵守：

1. **动作只在 `=` + 函数调用时求值**。`-=` 会被 `parseActionLine` 拼成 `"-" + value`（`internal/neko/parserRule.go:124`），接函数或 `$` 路径都会写成字面量字符串。
   - 错误写法：`$.代谢.能量储备 -= 代谢消耗热量()`
   - 正确写法：`$.代谢.能量储备 = 代谢能量储备下一步()`
2. **算术必须在 `@函数` 里**，动作值不支持表达式（`a / b` 会被当字面量）。
3. **除法返回浮点**；写回整型字段前用 `int()`，否则浮点值会落进字段（首版体温曾出现 `367.92`）。
4. **`-=`/`+=` 接数字字面量是安全的**（编译为 add），只有接函数/路径才坏。
5. **规则按 `优先级` 升序执行**（`internal/engine/engine.go:190`，数值小的先执行），`docs/neko-script.md` 已同步为升序。
6. **实体缺失路径时写入不会报错，而是把字符串塞进去**；探针里 `身体.*` 缺失导致 `代谢投影体力()` 被当字面量写入。上线前必须确认目标实体有对应字段（或先迁移）。

## 11. L1/L2 实测补充（2026-11-14）

### 11.1 动作值里的 `$.路径` 是陷阱

`resolveOpValue` 对以 `$` 开头的值只剥掉 `$`，于是 `$.循环.灌注` 交给 resolver 的键是 `.循环.灌注`（前导点），
`ParseEntityPath` 解析失败 → 值原样写进字段（字符串），后续函数读到字符串会报 `不支持的类型组合: int64 * string`。

| 写法 | 结果 |
|---|---|
| `$.器官.肝.灌注 = $.循环.灌注` | ❌ 写成字面量 `"$.循环.灌注"` |
| `$.器官.肝.灌注 = 循环.灌注` | ❌ 写成 `"$循环.灌注"`（裸路径被当实体选择器） |
| `$.器官.肝.灌注 = {e}.循环.灌注` | ✅ 解析为 94 |

**规则**：动作值跨字段引用一律写 `{e}.路径`；目标仍可写 `$.路径`。这是脚本层规避，不是语义设计。

## 12. 团队并行收口（L4 / L5 / 引擎修复）

### 12.1 新增层

### 12.2 已冻结的两个取舍

1. **孕周口径 = 1 游戏日 1 孕周**（压缩 7 倍）。原因：`流逝分钟` 单 tick 上限 1440，模板无分钟累加字段，按 7 天 = 1 周会永久整除为 0。要医学口径需新增 `生殖.孕期分钟` 累加字段。
2. **规则条件避免「∧ + 括号内 ∨」**：实测复合条件不稳，妊娠推进拆成 3 条单条件规则（5200/5210/5220），状态迁移按状态各一条（5400/5410/5420）。

### 12.3 引擎修复（task-3）

`internal/engine/ops.go` 的 `resolveOpValue` 新增 `resolveDollarValue`：
- `$.路径` → 归一为 `{e}.路径`；
- 裸 `$路径` 先按原义解析，失败回退 `{e}.路径`；
- `$1/$2`、`$[...]`、裸 `$` 维持旧语义。
- 新增 `internal/engine/opsDollarRef_test.go`，三种写法均解析为当前实体字段。

### 12.4 测试基线

`go test ./internal/engine` 全绿。`funcCall_test.go` 中依赖已删除旧语料（`scripts/kernel/behavior/cat_daily.neko`、`scripts/core/cat_core_v2.neko`）的 3 个用例改为「语料缺失则 skip」，语料恢复后自动生效。

### 12.5 路径 / 穿透子层（L3 内）

`scripts/kernel/injury/path{Model,Functions,Tick}.neko`，优先级 4000/4010，位于伤害累积（4200）之前。

| 字段 | 含义 |
|---|---|
| `路径.类型` | 无 / 口 / 肛 / 阴道 |
| `路径.应力` | 上层行为写入的归一化强度 0–100 |
| `路径.屏障阈值` | 口 80 / 肛 60 / 阴道 70 / 无 100 |
| `路径.破口` | 应力 ≥ 阈值 |
| `路径.屏障完整性` | 破口后每 tick 扣 应力/10 |
| `路径.污染` | 破口后累加（肛 +12、阴道 +8、口 +5） |

### 12.6 多主体动作值（$1/$2）修复

`resolveDollarValue` 增加 `$N` 分支：保留 `"$N."` 前缀先交给多主体 resolver（它只认该形态），失败再退回旧的「剥 `$`」行为。
`internal/engine/opsMultiDollar_test.go` 覆盖：`$2.身体.体力` 写入对方字段、缺失路径保持字面量。

## 14. 行为层与孕产生理（本轮）

### 14.1 行为层（优先级 900，早于 L0）

`scripts/kernel/behavior/behavior{Model,Functions,Tick}.neko`：

- 输入：类型（无/性行为/自慰/运动）、唤起、强度、润滑、经验、酒精、伙伴数、体内暴露。
- 派生输出（同一 tick 内被下游消费）：`应激输出`、`能耗输出`、`心率增量`、`催产素量`。
- 接线：L0 能量 += 能耗输出；L1 心率 += 心率增量、内分泌.催产素 ← 催产素量；L3 路径应力 = 行为应激（>0 时覆盖外部值）；L4 受孕要求 `行为.体内暴露 = true`。
- 唤起在「类型=无」时每 tick 衰减 10。

实测（性行为：唤起80/强度70/润滑30/经验50）：应激 63、能耗 22 kcal/tick、心率 +34、路径破口（肛阈值 60）。

### 14.2 孕产生理

- 中孕 +340 kcal/日、晚孕 +452、产后（哺乳）+500；血容量系数 130%/145%/100%。
- **L0 直接读 `生殖.怀孕状态` 计算**，避免「L4 在 tick 后段写、L0 用旧值」的滞后（曾导致血容量晚一 tick 生效）。
- 实测：中孕 20 周 → 能量需求 340、血容量系数 130、血液 4900→5865、体温 37.6°C、心率 118。

### 14.3 体温稳态修正

原散热公式按小时标定，在「1 天」tick 下会热失控（体温冲到 43°C 上限）。改为：

```
新温 = 当前 + (产热 − 散热)/45 − (当前 − 368)/20
```

`−（当前−368)/20` 是稳态回拉项，保证任意 tick 长度都收敛到 36.8°C 附近。

### 14.4 仍缺

死亡/MODS/后遗症、分娩出血（字段已留）、妊娠并发症（子痫/早剥/破裂）、路径数据化、叙事与事件集成、真实实体迁移。

## 15. 终局链：MODS / 死亡 / 后遗症 / 分娩出血

- `伤害.多器官衰竭` = 脑/心/肺/肝/肾 功能缺损均值。
- `伤害.死亡` = 休克 ≥100 ∨ MODS ≥90 ∨ 灌注 ≤5。
- `伤害.后遗症` 首次写定不覆盖：感染≥70→脓毒后遗症；失血≥80→慢性贫血；脑完整性<30→神经损伤。
- `状态.身体` 死亡优先于一切状态词。
- 分娩出血：晚孕→产后 且 `分娩已结算=false` 时，一次性给 `伤害.出血速率=20`、`分娩出血=20`。

## 20. 种族特征改为组合式

`基础.特性` 退化为**纯叙事标签**（展示/判定，无机制）；带机制的种族特征改为 `@实体` 组合：

```neko
@定义 猫耳 { "猫耳": {"灵敏[int]": 50} }
@实体 NPC:猫娘 [NPC, 猫耳, 猫尾, 肉垫] {}
```

- 特征模板：猫耳/猫尾/肉垫/犬耳/犬尾/狐耳/狐尾/尖耳（`scripts/kernel/traits/traitsModel.neko`）。
- 种族类型：NPC:猫娘 / NPC:犬娘 / NPC:狐娘 / NPC:精灵 / NPC:人族（`traitsTypes.neko`）。
- 属性加成读取特征字段（缺路径按 0，不影响无特征类型）：感知 += 耳灵敏/10、敏捷 += 尾平衡/2。
- 限制：`@实体` 不允许子覆盖父字段，所以特征**数值**由 B 层按 `基础.种族` 初始化写入；类型只提供字段结构。

实测：`NPC:猫娘` 实体 → 猫耳.灵敏 50、猫尾.平衡 10、肉垫.静音 20；感知 65 = 50+10+5，敏捷 70 = 50+15+5。
