# L6 物品 / 交互层（素材、食物、可交互动作）

本层补全「素材」的定义缺口：物品不再是一个只有 6 个字段的占位模板，而是**一个素材 = 一个实体**，
带数量/耐久/重量，按类型分食物、饮品、工具、容器、衣物；角色通过**交互意图**（拾取/吃/喝/给/用…）
与本层结算。脚本层只定义形状与结算规则，具体物品是数据层实例。

优先级段 **7000–7999**（在 L4 生殖 5000–5999 之后、L5 状态投影 9000 之前）。

## 1. 模板与实例类型

| 模板 | 文件 | 作用 |
|---|---|---|
| `素材` | `scripts/kernel/material/materialModel.neko` | 公有账本：名称/所属场景/持有人/数量/重量/耐久/品质/标签 |
| `食物内核` | 同上 | 食物账本：热量/水分/饱腹/口味/烹饪/可食/中毒风险/保质期/腐败 |
| `饮品内核` | 同上 | 饮品账本：水分/热量/酒精/咖啡因/温度/可饮/保质期/腐败 |
| `工具内核` | 同上 | 工具账本：用途/最大耐久/磨损/可修理 |
| `容器内核` | 同上 | 容器账本：容量/当前量/内容/密封/保温 |
| `衣物内核` | 同上 | 衣物账本：部位/保暖/防护/已穿戴 |
| `交互内核` | `scripts/kernel/interact/interactModel.neko` | 角色侧：动作/目标/对象/数量/状态/结果 |

实例类型（数据层创建时用）：`食物`、`饮品`、`工具`、`容器`、`衣物`，都继承 `素材` 的公有账本。
`@规则[$[素材]]` 通过祖先链同时匹配这五种类型。`交互内核` 已加入 `@实体 角色基础` 组合（`scripts/kernel/metabolism/metabolismAttach.neko`）。

单位：重量 g、体积 mL、热量 kcal、水分 mL、耐久与品质 0–100、时间 分钟。

### 一个素材实例

```json
{
  "类型": "食物", "类别": "食物", "名称": "苹果",
  "所属场景": "K1", "持有人": "", "可用": true, "数量": 3,
  "重量": 180, "耐久": 100, "品质": 50,
  "描述": "一颗脆苹果",
  "食物": { "热量": 95, "水分": 85, "饱腹": 20, "保质期": 10080, "可食": true }
}
```

- **名称在同一场景内唯一**：交互用 `名称` 作目标句柄（`交互.目标 = "苹果"`）。
- `所属场景` 是它摆在哪；`持有人` 非空表示被角色拿走（此时仍在原场景账上，但交互优先看持有人）。
- `数量` 是这一实体代表几份；吃到 0 时 `数量<=0` 规则自动 `可用=false` 并把 `持有人` 清空。
- `保质期` 单位分钟，`0` 表示不会坏；`腐败` 0–100，过 70 `可食/可饮` 变 false。

## 2. 交互协议

上层（行为、LLM、其它脚本）**只写意图**，本层在同一 tick 内校验并结算，结算后清空意图：

```json
"交互": { "动作": "吃", "目标": "苹果", "对象": "", "数量": 1, "状态": "空闲", "结果": "" }
```

1. 写 `交互.动作` + `交互.目标`（+ `对象`/`数量`）。
2. 跑一次 tick。
3. 读 `交互.状态`（`完成`/`失败`）与 `交互.结果`（人类可读一句话）；动作与目标已被清空，不会重复执行。

动作词表：

| 动作 | 目标 | 前置 | 结算 |
|---|---|---|---|
| `拾取` | 素材 | 未持有、同场景、角色有名字 | `持有人 = 角色名字` |
| `放下` / `丢弃` | 素材 | 本人持有 | `持有人=""`、`所属场景=角色场景` |
| `给予` | 素材 | 本人持有、`对象` 非空 | `持有人 = 对象` |
| `查看` | 素材 | 本人持有，或未持有且同场景 | `结果 = 素材.描述` |
| `使用` | 素材 | 本人持有、`可用` | `耐久 -1`（具体效果由上层按标签再结算） |
| `穿戴` / `脱下` | 衣物 | 本人持有 / 已穿戴 | `衣物.已穿戴` 翻转 |
| `吃` | 食物 | 本人持有、`数量>0`、`可食` | `数量-1`、热量进 `代谢.胃内容`、水分进 `代谢.摄入液`、中毒风险入 `伤害.感染/疼痛` |
| `喝` | 饮品 | 本人持有、`数量>0`、`可饮` | `数量-1`、水分进 `代谢.摄入液`、酒精进 `代谢.酒精`、少量进胃内容 |

没有素材能对上（目标不存在/不可用/没拾取/不在同一场景）→ 兜底规则把状态标 `失败`、
结果写「无法完成：目标不可用」，并清空意图。

吃/喝的效果落在 `代谢.胃内容`/`代谢.摄入液` 上，由 L0 的下一个 tick 吸收（一次 tick 的延迟）；
`身体.饱食` 由 L5 投影从胃内容算，因此吃完当 tick 就能看到饱腹上升。

## 3. 被动结算

| 规则 | 优先级 | 作用 |
|---|---|---|
| `mtSpoilFood` / `mtSpoilDrink` | 7000 / 7010 | 按 `世界.状态.每tick分钟` 推进腐败；过 70 不可食/饮；腐败推高中毒风险 |
| `mtDeplete` | 7260 | `数量<=0` → `可用=false`、清空持有人 |
| `mtWearOut` | 7270 | `耐久<=0` → `可用=false` |

物品层是 `世界` 单例的消费者：变质速度读 `世界.状态.每tick分钟`。世界实体缺失时变质规则会报错，
因此数据层必须保留 `世界` 单例（`scripts/kernel/world/worldModel.neko`）。

## 4. 引擎约束（写新物品/交互规则前必读）

1. **多主体规则头用全角逗号** `，`：`@规则[$1[交互内核]，$2[素材]]`。ASCII `,` 会被当成类型名的一部分
   （`internal/neko/parserRule.go:71` 只按 `，` 切分），编译出的 subjects 会变成一条错误选择器。
2. **多主体条件不要用括号分组的 `∨`**：`(A ∨ B)` 在多主体条件下不成立；需要「二选一」就拆成两条规则
   （本层用 `ixInspect` / `ixInspectScene` 示范）。
3. **动作块用条件花括号形式**：`条件 { 动作行 }`，每行一个动作。`动作:` 键的续行会被拼成一段文本，
   只能解析出一条动作。
4. **`-=` 只接字面量**：`$2.数量 -= 1` 可以；`-= 函数()` / `-= 路径` 会被当字面量写入。
5. **跨实体写入只走多主体 `$N.路径`**：单主体规则里不能写别的实体，读别的实体用 `@函数` 里的
   `实体ID.路径`（如 `世界.状态.每tick分钟`）。

## 5. 数据层迁移

`素材` 模板从 6 个字段扩到 12 个字段、并新增 5 个内核与类型；`交互内核` 也加进了 `@实体 角色基础` 组合。
注册表对已注册模板的**父列表变更会拒绝**（`internal/registry/templateGuard.go`），所以升级后必须重置派生数据：

```bash
rm -rf ~/.dsh-neko/Neko/data/templates ~/.dsh-neko/Neko/data/scripts.json
```

`templates/` 与 `scripts.json` 都是从 `scripts/` 派生的，删掉后运行时启动会重新引导（`make install-runtime` 已内置这两步）。
`entities.json`、`journal/`、`experts.json` 是权威数据，不要删。

已有的旧 `素材` 实例不会自动补字段：

- 旧实例缺 `数量/重量/耐久/品质/标签/类别`，交互规则读不到这些路径 → 需要**重建**（或数据层补默认值）。
- 新建素材时按语义选类型：`食物` / `饮品` / `工具` / `容器` / `衣物`，并把对应内核字段一起写入。
- 场景的 `物品` 列表是场景侧描述，交互结算不依赖它；物品靠自己的 `所属场景` 归属。

## 6. 验证

```bash
GOCACHE=$PWD/.local/gocache go run ./.local/probe
```

探针的 `material phase` 覆盖：拾取 → 吃（数量、胃内容、饱食）→ 拾取+喝（数量、摄入液）→
拾取+使用（耐久归零、可用转 false）→ 查看（结果=描述）→ 放下 → 穿戴/脱下 → 给予 →
目标不存在（失败兜底）→ 腐败 69→70（可食转 false、吃不动）。

实测输出（2026-11-14）：

```
pickup holder=猫猫 result=拿在手里 status=完成
eat 数量 3 -> 2 胃内容=95 饱食=6
drink 数量=1 摄入液=500
use knife 耐久=0 可用=false
inspect result=一颗脆苹果
drop holder="" scene=K1
wear=true then off=false
give holder=梦梦 result=完成
missing target status=失败 result=无法完成：目标不可用
spoil=70 edible=false
```
