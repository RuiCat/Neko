# L7–L11 认知 / 社会层：行动、规划、教育、交易、记忆

这五层补的是角色「做什么、怎么排、怎么学、怎么换、记得什么」的底层状态机。
它们只维护**状态与派生量**，不猜测剧情；决策内容（学什么、买什么、记住什么）由上层
（LLM / 行为脚本 / 数据层）写入意图字段，本层负责推进、校验与结算。

优先级段 **8000–8999**（在 L6 物品/交互 7000–7999 之后、L5 状态投影 9000 之前）：

| 层 | 优先级 | 目录 | 内核模板 | 写域 |
|---|---|---|---|---|
| L7 行动 | 8000–8099 | `scripts/kernel/action/` | `行动内核` | `行动.*` |
| L8 规划 | 8100–8199 | `scripts/kernel/plan/` | `规划内核` | `规划.*` |
| L9 教育 | 8200–8299 | `scripts/kernel/education/` | `教育内核` | `教育.*` |
| L10 交易 | 8300–8399 | `scripts/kernel/trade/` | `交易内核` | `交易.*` + 素材的 `持有人/数量`（成交转移） |
| L11 记忆 | 8400–8499 | `scripts/kernel/memory/` | `记忆内核` | `记忆.*` |

同优先级按注册顺序；每层只写自己内核的字段（交易层写素材归属是唯一例外，见 §5）。
所有内核都会加入 `@实体 NPC` 组合（`scripts/kernel/metabolism/metabolismAttach.neko`），由 Lead 统一接线。

## 1. L7 行动（`scripts/kernel/action/`）

`@定义 行动内核`：

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `行动.当前` | str | 正在做的动作：`进食`/`休息`/`移动`/`工作`/`学习`/`交谈`/`无` |
| `行动.阶段` | str | `空闲`/`执行`/`完成`/`中断` |
| `行动.目标` | str | 目标句柄（物品名/场景 id/对象名） |
| `行动.对象` | str | 交互对象（人） |
| `行动.进度` | int 0–100 | 百分比 |
| `行动.已用分钟` | int 0–1440 | 已花时间 |
| `行动.总分钟` | int 0–1440 | 计划耗时，0 = 未设置（按 60 处理） |
| `行动.被打断` | bool | 上层置 true 表示主动打断 |
| `行动.中断原因` | str | `被打断`/`生理需求`/`休克` |
| `行动.结果` | str | 完成/中断时的一句话 |
| `行动.能耗` | int 0–500 | 本行动的代谢开销（只记录，不写代谢字段） |

状态机（规则 id 前缀 `ac`，优先级 8000–8099）：

1. `当前=""` 且阶段非空闲 → 阶段/进度/已用/总分钟清空、结果清空。
2. `当前!=""` 且阶段 `空闲` → 阶段 `执行`、已用 0、进度 0；`总分钟=0` 时按 60 计。
3. 阶段 `执行` 且 `流逝分钟>0`：`已用 += 流逝分钟`（不超总分钟）；`进度 = 100*已用/总分钟`；
   进度到 100 → 阶段 `完成`、结果 `完成`、`当前=""`。
4. `被打断=true` → 阶段 `中断`、中断原因 `被打断`、清 `当前`、`被打断=false`。
5. `规划.紧迫度 >= 90` 且阶段 `执行` → 阶段 `中断`、中断原因 `生理需求`、清 `当前`。
6. `伤害.休克 >= 50` 且阶段 `执行` → 阶段 `中断`、中断原因 `休克`、清 `当前`。

能耗派生：`行动.能耗 = 行动能耗()`，当前为空时 0，否则 `总分钟/6 + 已用分钟/12`，上限 500。

## 2. L8 规划（`scripts/kernel/plan/`）

`@定义 规划内核`：

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `规划.目标` | str | 当前目标文本/id |
| `规划.阶段` | str | `空闲`/`执行`/`评估`/`达成`/`放弃` |
| `规划.优先级` | int 0–100 | 上层写入；0 = 放弃 |
| `规划.进度` | int 0–100 | 上层推进 |
| `规划.步骤` | list | append-only 计划文本（上层 `+=` 追加） |
| `规划.重规划` | bool | 上层置 true 请求重排 |
| `规划.紧迫度` | int 0–100 | 派生：max(饥饿, 口渴, 疲劳, 疼痛) |
| `规划.结果` | str | 达成/放弃/评估时的一句话 |

规则（前缀 `pl`，8100–8199）：

1. 每 tick 写 `紧迫度 = 规划紧迫度()`（读 `代谢.饥饿`/`代谢.口渴`/`睡眠.疲劳`/`伤害.疼痛`）。
2. `目标=""` → 阶段 `空闲`、进度 0、结果清空。
3. `目标!=""` 且阶段 `空闲` → 阶段 `执行`。
4. `重规划=true` → 阶段 `评估`、`重规划=false`、结果 `需要重规划`。
5. `进度>=100` → 阶段 `达成`、结果 `达成`、`目标=""`。
6. `优先级<=0` 且阶段 `执行` → 阶段 `放弃`、结果 `放弃`、`目标=""`。

## 3. L9 教育（`scripts/kernel/education/`）

`@定义 教育内核`：

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `教育.科目` | str | 阅读/书写/算术/料理/格斗/礼仪… |
| `教育.熟练` | int 0–100 | 该科目累计熟练度 |
| `教育.学习进度` | int 0–100 | 当前一档的进度 |
| `教育.学习效率` | int 10–300 | 派生：智力/疲劳/师从 |
| `教育.专注` | int 0–100 | 上层写入的专注度 |
| `教育.师从` | str | 老师实体名字，空 = 自学 |
| `教育.已学分钟` | int 0–525600 | 累计学习分钟 |
| `教育.水平` | str | 派生：`入门`/`熟练`/`精通`/`大师` |

规则（前缀 `ed`，8200–8299）：

1. 每 tick `学习效率 = 教育学习效率()`：`100 + 智力/4 - 疲劳/8 + （师从非空 ? 30 : 0）`，夹在 10–300。
2. `行动.当前 == "学习"` 且 `流逝分钟>0`：`学习进度 += int(学习效率 * 专注 * 流逝分钟 / 60000)`；
   `已学分钟 += 流逝分钟`。
3. `学习进度 >= 100` → `学习进度 = 0`、`熟练 += 10`（上限 100）。
4. `水平` 由 `熟练` 派生：≥95 大师、≥80 精通、≥50 熟练，否则入门。

## 4. L10 交易（`scripts/kernel/trade/`）

素材新增字段 `素材.价格`（int，单位：货币），由数据层写入，交易层只读。

`@定义 交易内核`：

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `交易.货币` | int 0–1000000 | 持有货币 |
| `交易.意向` | str | `买`/`卖`/空 |
| `交易.标的` | str | 素材名称 |
| `交易.数量` | int 1–99 | 交易份数 |
| `交易.报价` | int 0–1000000 | 谈判价；0 = 按标价 |
| `交易.对象` | str | 交易对手名字（记录用） |
| `交易.成交额` | int 0–1000000 | 最近一次成交金额 |
| `交易.结果` | str | `成交`/`未达成`/… |
| `交易.声誉` | int 0–100 | 成交 +1 |

规则（前缀 `tr`，8300–8399，多主体 `$1[交易内核]，$2[素材]`）：

> 交易是**单件**的：只有 `素材.数量 = 1` 的标的能成交（引擎动作值不支持乘法，拆批要新建实体，
> 而脚本不能创建实体）。金额直接用 `交易.报价` 一个字段，不做 `价×量`。

1. `trQuoteBuy`（8300）：`意向="买" ∧ 标的=名称 ∧ 报价=0 ∧ 素材.价格>0` → `报价 = 素材.价格`。
2. `trBuy`（8310）：`意向="买" ∧ 标的=名称 ∧ 报价>0 ∧ 货币 >= 报价 ∧ 数量=1 ∧ 持有人 != 自己` →
   `货币 = 交易付款()`、`成交额 = 报价`、`素材.持有人 = 名字`、`结果="成交"`、`声誉 = 交易声誉下一步()`、清意向/标的/对象/报价。
3. `trQuoteSell`（8315）：`意向="卖" ∧ 标的=名称 ∧ 持有人=自己 ∧ 报价=0 ∧ 素材.价格>0` → `报价 = 素材.价格`。
4. `trSell`（8320）：`意向="卖" ∧ 标的=名称 ∧ 持有人=自己 ∧ 报价>0 ∧ 数量=1 ∧ 对象 != ""` →
   `货币 = 交易收款()`、`成交额 = 报价`、`素材.持有人 = 对象`、`结果="成交"`、声誉 +1、清意向。
5. `trFail`（8390）：`意向 != ""`（没被上面任何规则清掉）→ `结果="未达成"`、清意向/标的/对象/报价。

**已知边界（必须写进脚本注释）**：货币不从交易对手账上扣/加（跨实体第三写不支持），
`交易.对象` 只作记录；买整批（`素材.数量` 必须等于 `交易.数量`），不做拆分。

## 5. L11 记忆（`scripts/kernel/memory/`）

`@定义 记忆内核`：

| 字段 | 类型/范围 | 含义 |
|---|---|---|
| `记忆.短期负荷` | int 0–100 | 当前工作记忆占用 |
| `记忆.长期负荷` | int 0–100 | 巩固后的长期记忆量 |
| `记忆.回忆强度` | int 0–100 | 派生：(长期负荷+情绪印记)/2 |
| `记忆.情绪印记` | int 0–100 | 强烈情绪事件的残留 |
| `记忆.遗忘速率` | int 1–100 | 短期衰减速度，默认 10 |
| `记忆.遗忘阈值` | int 0–100 | 短期低于它即遗忘，默认 10 |
| `记忆.巩固` | bool | 上层置 true 请求巩固 |
| `记忆.最近事件` | list | append-only 文本（上层 `+=`） |

规则（前缀 `me`，8400–8499）：

1. 短期衰减：`短期负荷 -= int(遗忘速率 * 流逝分钟 / 600)`，下限 0。
2. 巩固：`巩固=true` → `长期负荷 += 短期负荷/2`（上限 100）、`短期负荷 -= 短期负荷/2`、`巩固=false`。
3. 长期缓慢遗忘：`长期负荷 -= int(流逝分钟 / 720)`，下限 0。
4. 情绪印记衰减：`情绪印记 -= int(流逝分钟 / 1440)`，下限 0。
5. 遗忘：`短期负荷 < 遗忘阈值` 且 `短期负荷 > 0` → `短期负荷 = 0`。
6. 每 tick `回忆强度 = (长期负荷 + 情绪印记) / 2`。

## 6. 跨层只读约定

- 行动读 `规划.紧迫度`、`伤害.休克`、`代谢.流逝分钟`；
- 规划读 `代谢.饥饿`、`代谢.口渴`、`睡眠.疲劳`、`伤害.疼痛`；
- 教育读 `行动.当前`、`基础.属性.智力`、`睡眠.疲劳`、`代谢.流逝分钟`；
- 交易读 `素材.价格`；
- 记忆只读 `代谢.流逝分钟`；
- **不跨层写**。唯一例外：交易成交时写素材的 `持有人`（物品转移的本质），已在 §4 声明。

跨实体读取一律用 `@函数` 里的 `实体ID.路径`（如 `世界.状态.每tick分钟`），不要在条件里写动态实体名。

## 7. 引擎约束（新写规则必读）

1. **多主体规则头必须用全角逗号 `，`**（`internal/neko/parserRule.go:71` 只按 `，` 切分）。
2. **多主体条件不要用括号分组的 `∨`**（`(A ∨ B)` 不成立），需要二选一拆成两条规则。
3. **动作块用花括号形式** `条件 { 每行一个动作 }`；`动作:` 键的续行只能解析出一条。
4. **`-=` 只接字面量**；算术放 `@函数`，规则里写 `字段 = 函数()`。
5. `@函数` 比较用 `==`；除法结果是浮点，赋值给 int 字段前用 `int()`。
6. 跨实体读：`实体ID.路径` 可用；跨实体写只有多主体 `$N.路径`。
