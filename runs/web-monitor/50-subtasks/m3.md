# 子任务 m3：后端监视服务

## 职责

在 `bin/dsh-mcp` 进程内提供 `/monitor/api/*` 与 `/monitor/ws`，复用 `bootstrap.Runtime` 与 `mcpserver` 的 tick/写 gate；
新增引擎观察钩子（tick/诊断/新实体），统一 `/state` 的 path 语义；不改 MCP 工具集合。

## 输入 / 输出

- 输入: K1/K2/K3/K5/K6 契约；`bootstrap.Runtime`（Store/Machine/Registry/Diagnostics/Funcs）；`mcpserver.TryRunTick`/`WithStateWrite`。
- 输出: `internal/monitor`（server.go + api/ + ws/ + auth/ 子包）；`cmd/dsh-mcp/main.go` 接线；`internal/control/state.go` 改走 `Entity.Get`；
  `internal/mcpserver` 的 tick 观察者 setter；`internal/diagnostics` 的 `SetNotify`；`internal/bootstrap` 的接线；`go.mod` 加 `github.com/coder/websocket`。

## 契约引用

- 我消费: K1 K2 K3 K5 K6（`40-plan.md`）
- 我产出: 上述实现；K1–K3 的字段/错误码/帧格式以契约为准，不得改。

## 边界（不做什么）

- 不写 `internal/monitor/web/**`（m5/m6 写）；不写 `design/**`（m2/m4 写）；不改 `Makefile`（m7 写）。
- 不改 `/health` `/tick` `/session-event` 的既有语义；只允许 `/state` 的 path 查询按 K5 改走 `Entity.Get`（D2 裁决）。
- 不引入除 `github.com/coder/websocket` 外的运行时依赖；不引入 node 构建链。
- 不把监视器做成独立进程；不新增第二个可写 `data/` 的入口。

- 每次 bash 调用是独立环境；持久产物写上述写域；多步验证放同一次调用。
- 构建/测试统一 `make` 或 `go test`（GOCACHE/GOMODCACHE 已在 Makefile 导出；可 `source` 或直接 `make`）。
- 项目无 `.agent-memory/`：跳过记忆读协议，不中断任务。
- 只写上述路径；`internal/entity`、`internal/engine`、`internal/registry`、`internal/events`、`internal/function`、`internal/config` 只读。
- 不要请求提权；不要联网安装；需要在宿主观察运行中进程时写命令交回 Lead。
