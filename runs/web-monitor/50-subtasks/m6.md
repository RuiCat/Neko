# 子任务 m6：组合装配

## 职责

按 `composition.json` 把 m5 的元件装配成页面：`index.html`（入口/布局/插槽）+ `app.js`（数据获取与状态渲染、WS 客户端接线）+ `app.css`（仅布局/响应式）；
组合层只做装配，不新造原子、不覆盖元件内部样式。

## 输入 / 输出

- 输入: K1/K2/K4 契约；m5 的元件实现；`design/composition.json`。
- 输出: `internal/monitor/web/index.html`、`app.js`、`app.css`、`wsClient.js`（WS 连接/重连/订阅/帧分发）。

## 契约引用

- 我消费: K1（REST 字段）、K2（WS 帧）、K4（组合树）；元件契约（m4）
- 我产出: 可加载的页面入口 + WS 客户端（m7 的 e2e 与人工验收对象）
- 契约原文（冻结，不得自行更改）:

  ```text
  K2：每次连接（含重连）hello 后必发 snapshot；无 resumeSeq；delta 只在 snapshot 后；
      慢消费者丢 delta 后补 snapshot；客户端按 type 分发。
  K4：组合层不新造原子元件、不用 !important/行内 style/深选择器覆盖元件内部样式。
  ```

## 边界（不做什么）

- 不写 `design/**`（m2/m4）、不写 `internal/monitor/web/components/**`（m5）、不写 Go 后端（m3）。
- 不在组合层直接写 `<button>` 等未登记原生标签实现业务控件（先回 m4 登记）。
- 不引入前端框架/打包器。
